# 索引台 · 前端设计系统

> 本文件是 `python/api/static/` 的视觉事实源。改界面前先读这里；
> token 的唯一定义处是 `python/api/static/app.css` 的 `:root`，本文件与之保持同步。

## 1. 设计立场

AgentKnowledgeHub 的核心能力不是"聊天"，而是**可追溯**：每条答案背后有四条权重不同的检索通道、
带章节路径的文档块。旧界面把这些塞进折叠的 `<details>`，
等于把最值钱的差异化资产做成了附属信息。

因此整套界面的结构主线是**出处**，而不是对话气泡：
问答页右侧的「本次检索」是常驻栏，不是可折叠面板。

视觉隐喻：档案室的**索引台**——黄铜刻度、台账、可核验的引证。界面语言取自产品自己的词汇
（台账、出处、通道、权重、块号），不取自通用的 AI 控制台词汇。

## 2. 色彩

底色刻意避开三类高频套路：奶油底 + 衬线 + 赭石、纯黑 + 荧光强调色、藏青 + 蓝紫渐变
（旧版的 `#07101f` 正是第三种）。

| Token | Hex | 名 | 用途 |
|---|---|---|---|
| `--ground` | `#0E1A1C` | 氧化墨 | 页面底色 |
| `--surface` | `#14262A` | 案面 | 面板 / 溯源栏 |
| `--surface-2` | `#1B3237` | 抬升 | 悬停、选中 |
| `--sunken` | `#0A1416` | 凹槽 | 输入框、索引脊 |
| `--rule` / `--rule-2` | `rgba(167,199,193,.16)` / `.30` | 划痕 | 分隔线（带绿调，不用中性灰） |
| `--ink` | `#E7EDE9` | 纸白 | 主文字 |
| `--ink-2` | `#91A6A2` | 淡墨 | 次要文字 |
| `--ink-3` | `#6D827F` | 灰墨 | 元信息、占位 |
| `--brass` | `#C8A24A` | 黄铜 | **唯一强调色**：焦点环、活动刻度、引证序号 |
| `--seal` | `#C4544A` | 印泥 | 仅错误 |
| `--vital` | `#4FA98C` | 在位 | 仅运行状态 |

**纪律**：强调色只有黄铜一种。状态色（印泥/在位）只在真正的状态语义上出现，
不做装饰。功能色一律配文字，不靠颜色单独承载信息。

## 3. 字体

| 角色 | 字族 | 说明 |
|---|---|---|
| 标题 + 答案正文 | **Noto Serif SC**（思源宋体）400/600 | 让回答读起来像一份可归档的"答案笺" |
| 界面与数据 | **Noto Sans SC** 400/500/700 | 中文第一公民 |
| 机器标识 | **IBM Plex Mono** 400/500 | 关系类型、文件名、块号、计数；**仅用于机器串**，不做装饰性等宽标签 |

**中文尺寸下限**（旧版大量 10–11px 中文标签是真实的可读性问题）：

- 正文 14.5px（问答正文 15.5px，行高 1.95）
- 次要文字 12.5px
- 任何中文不低于 12px

**行宽**：问答正文 `--measure: 40em` ≈ 40 个汉字/行（中文舒适区），
不是拉丁文的 65–75ch。

**回退栈必须独立成立**（内网离线时页面仍要看起来是设计过的，语义不依赖 webfont）：

```
'Noto Serif SC','Source Han Serif SC','Songti SC','SimSun',serif
'Noto Sans SC','PingFang SC','Microsoft YaHei','Hiragino Sans GB',sans-serif
'IBM Plex Mono','SFMono-Regular',Consolas,'Liberation Mono',monospace
```

字体经 Google Fonts 加载（unicode-range 分片 + `font-display:swap`），
并已 `preconnect`。若部署环境完全不能外联，去掉 `<link>` 即可，视觉略降但不破相。

## 4. 版式

### 骨架

```
┌───────────┬────────────────────────────────────┬──────────────────┐
│ 索引脊 264 │  检索栏  --measure                  │  溯源栏  336     │
│ 导航      │  问题（宋体）                        │  按通道分组的出处 │
│ 台账      │  答案（宋体）                        │  通道权重 ×       │
│ 系统状态  │  引证行 [1][2][3]                   │  重排得分         │
│           │  读数 / 通道筛选                     │  检索过程         │
└───────────┴────────────────────────────────────┴──────────────────┘
```

- **索引脊**不是图标导航：它是本工作区的实时台账（文档 / 实体 / 关系 / 向量块），
  等宽数字贴着分隔线对齐；导航项只有 2px 黄铜刻度 + 文字。
- **溯源栏在问答页常驻**，`<1000px` 变成底部抽屉 + 常驻把手（不藏进 disclosure）。
- 没有顶栏：视图标题在各自视图内，系统状态在索引脊，避免重复 chrome。

### 圆角与阴影

`--r-panel: 2px`（面板）· `--r-ctl: 6px`（控件）· 导轨类 0 圆角。
每层一个值，不再全站统一 14/20px。阴影只在浮层（toast）使用，取消渐变洗底。

### 间距

4/8 节奏：4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 56。

## 5. 动效

**只有一处编排**：答案到达时，溯源栏条目按检索顺序**依次盖章进入**
（`stamp` 关键帧，40ms 错峰，只动 transform/opacity）。它对应"检索 → 溯源"的真实因果。

其余全部 150–250ms 状态过渡。**不做**整页淡入上移、不给每张卡片加 hover 位移。
`prefers-reduced-motion: reduce` 下全部即时呈现。

## 6. 内容与措辞

- 按钮用动词说清结果：`发送`、`刷新`——同一动作在流程里保持同一名字。
- 空状态是行动的邀请，不是情绪：检索无结果时给"换个说法再试"，而不是"暂无数据"。
- 错误说清原因 + 下一步：`检索失败：<原因>`，不道歉、不含糊。
- **禁止**：全大写 eyebrow 分组标签、`A · B · C` 圆点串联的元信息串、
  `WORD — 片段` 式标签、按钮文字后加 `→`、emoji/dingbat 当图标。
- 编号只在内容真的是序列时使用：引证序号、检索步骤、入库阶段。

## 7. 可访问性

- 焦点环：2px 黄铜 + 2px offset，不被粘性元素遮挡。
- 交互目标 ≥ 24×24 CSS px（WCAG 2.2），主要触摸目标 ≥ 44px。
- `prefers-reduced-motion` 全局生效。
- 图标按钮有可访问名称；装饰性图标 `aria-hidden="true"`。
- 动态区域用 `aria-live="polite"`：toast、答案加载、入库进度。
- 色觉：状态一律"文字 + 颜色"双编码。

## 8. 已知的设计取舍

1. **引证不做句级内联**。后端 `POST /api/qa/ask` 只返回按重排得分排序的
   `sources` 集合，没有"哪一句对应哪一条"的映射；凭空在句子后插标就是编造溯源，
   与"可核验"的产品立场冲突。因此引证集中在答案末尾一行，并注明排序依据。
   若将来后端返回句级归属，这里应改成内联上标。
2. **分值的含义要与后端一致**。排序依据是 cross-encoder 的重排得分
   （`QAAgent._rerank_contexts` 写入 `score`），不是"相关度"。
   界面上展示通道与得分，让排序原因可见，而不是把一个加权过的分数谎称为相关度。
